# Architecture

## Boundaries

- `SentinelHUD.Core` is platform-neutral. It owns configuration data/defaults/migration, formatting, shield-segment math, conditional visibility, resolution-safe layout math, PvP threat classification and awareness policies.
- `SentinelHUD` is the API 15 Dalamud plugin. It resolves transient game objects every frame, renders modules, owns the configuration window and uses the official game/data services.
- `external/SentinelCore` is pinned to an immutable commit. Selected Core projects are compiled and packaged with this plugin; there is no shared runtime plugin.

## Rendering

HUD modules are independent, titleless, input-free ImGui windows in both locked and unlocked modes. They therefore have one invariant outer origin and cannot drift when editor state changes. `HudEditorInteractionRenderer` adds a separate transparent input layer only while unlocked: the module body moves the normalized anchor, left/right edges change explicit Width, top/bottom edges change Bar Height, and corners change both. Top/left resizing compensates the saved origin so the opposite edge remains stable. Foreground borders, labels and grips provide edit feedback without entering layout calculations. Moves and resizes are clamped to the viewport and debounced for persistence. Width and bar height are explicit dimensions, while Scale changes typography/style without distorting text or icons.

Health/MP/cast bars are Sentinel-rendered primitives. `ShieldBarPolicy` calculates an extension segment in unused HP space and an overlay segment for overflow/full-HP shields, keeping all colours inside one fixed bar. `HpColourPolicy` is platform-neutral and either preserves the resolved static role/disposition colour or continuously interpolates low-red → mid-yellow → high-green from current HP fraction. Target disposition uses Dalamud's supported character hostile/party/alliance/friend flags only in static mode. Player casting uses the same cast renderer as Target and Focus with independent field switches and no idle placeholder. The optional exact-HP supplement probes both combined `_TargetInfo` and split `_TargetInfoMainTarget`, anchors to the visible HP component's `GetBounds` result and draws through the foreground overlay; it never edits native nodes.

Game objects are never cached between frames. Player, target and focus references are resolved for the current draw only. Target-of-target and Focus Target's Target use the current parent actor's target ID and a direct object-table lookup. The Focus child interaction stores a relationship descriptor—not the resolved child—and repeats that chain at click time, so a changed/cleared Focus target cannot dispatch through a retained object. Static job metadata and action/status names are cached.

`ActorInteractionRenderer` is a reusable, explicit-input boundary for actor references. Locked module windows retain `NoInputs`; after content rendering, the helper creates transparent windows only over enabled whole-module, header/name or child-row regions. A mouse-position priority pass removes an overlapping lower-priority parent region whenever the Focus child row is under the pointer. `ActorReferenceResolver` handles both direct object IDs and relationship references, then `ActorTargetingService` checks current targetability and sets `ITargetManager.Target`. `ActorContextMenuService` uses that same resolver and calls the current `AgentHUD.OpenContextMenuFromTarget` path, allowing FFXIV to populate valid actor/context actions rather than maintaining a static menu. Before opening, `ContextMenuPlacementPolicy` chooses an on-screen right/left/below/above position beside the originating region and supplies it through `AgentContext.SetPosition`; once the native `ContextMenu` addon is visible, its scaled size is read and `AtkUnitBase.SetPosition` applies one exact correction. Visual modules never stop drawing or change layout. Only the transparent actor-input layer pauses while the menu is opening/visible, allowing menu selection and outside dismissal to reach FFXIV. No world-click simulation or native actor pointer is retained. Edit mode does not draw this interaction layer at all.

## Awareness services

`ISelfHighlightService` isolates low-level silhouette rendering from all HUD modules. `NativeSelfHighlightService` uses FFXIVClientStructs' current `GameObject.Highlight` virtual function on the validated local-player address. This changes draw-object outline state only and propagates through the game's own actor rendering. The official current structure exposes `ObjectHighlightColor` as a fixed byte palette (`None`, `Red`, `Green`, `Blue`, `Yellow`, `Orange`, `Magenta`, `Black`) and no arbitrary RGB field. Yellow/Green/Blue select exact entries. Custom RGB remains persisted and is resolved to the closest documented palette entry with the applied entry shown in UI/diagnostics. White fails closed because it has no documented exact entry; it is never substituted with Yellow. The service never sets any `ITargetManager` property. Disable/disposal clears only the current local actor; stale actor pointers are never retained across zone changes.

`PlayerPositionMarkerRenderer` reads the current local actor once per draw, uses the same login/combat/duty policy inputs as Self Highlight and casts one short downward terrain ray. Both rendering styles share that exact terrain-resolved centre and the same colour/danger policy. Camera Facing (the schema-8 default) projects the centre once and draws a fixed screen-space circle whose 0.01–0.60 size setting maps to a compact 1.0–19.2 px radius; it therefore remains circular at shallow camera angles and readable at extended zoom. Ground Projected retains the existing 24-point surface-plane disc. Its outer and inner point buffers are allocated once. Both borders fill inward, so border thickness never enlarges the outside radius. The camera-facing path follows Avarice's current one-projection screen-dot presentation principle but contains independent Sentinel-authored code and has no Avarice dependency.

## Encounter-awareness boundary

`EncounterAwarenessService` owns independent providers and exposes only cached `DangerArea` geometry plus a point-in-shape result. `DangerArea` is platform-neutral and implements X/Z containment for circles, donuts, forward rectangles, cones, finite-width lines and crosses with a vertical floor tolerance. The marker never knows whether a shape came from the client, Splatoon or a future Sentinel encounter profile.

`NativeCastDangerProvider` samples hostile casting battle NPCs at 50 ms intervals, caches static action-shape metadata, and emits geometry only for current actions that have a native omen and a supported standard cast type. Unknown or encounter-specific mechanics are skipped. `SplatoonDangerProvider` polls optional `Splatoon.IsLoaded` and `Splatoon.GetActiveDrawGeometryV1` IPC at 150 ms while enabled; install status is checked only every two seconds while disabled. Splatoon v1 shapes without explicit danger semantics are withheld unless the user enables the clearly labelled trust-all-visible-geometry option. No Splatoon/Avarice source is copied and neither plugin is a dependency.

## PvP threat-awareness boundary

`PvPThreatTracker` is a standalone Sentinel HUD runtime service. It samples the current object table at 125 ms, builds immutable presentation snapshots and never stores game-object pointers. Frontline classification uses the native zero-based `Character.Battalion` values 0/1/2 as the authoritative team discriminator. If those values cannot be trusted for the observed set, only this feature uses a conservative hostile-flag fallback that excludes the local player, party, alliance and roster allies. The platform-neutral `PvPThreatPolicy` owns those validity rules and the warning thresholds.

The runtime filters to live, targetable, non-dead enemy players whose current hard-target ID equals the local player's ID. Its snapshot separates targeting count, optional targeter rows, nearby enemy/ally density, classification source and diagnostic explanation from rendering. The borderless HUD module owns only layout, typography and warning colour. PvP Sentinel is neither referenced nor required, and no other Sentinel HUD system depends on the tracker.

## Camera boundary

`IExtendedCameraZoomService` isolates the optional camera write from the HUD and awareness renderers. It uses the current API 15 world-camera layout confirmed against Cammy and modifies only maximum zoom (plus current/interpolated zoom when clamping during restore). It captures the pre-existing maximum, restores it on disable/disposal and abandons stale pointers on camera replacement. It pauses in first person, GPose, cutscenes, territory transitions and while known camera-controller plugins are loaded. An unexpected writer trips a fail-closed conflict state rather than starting a per-frame write fight.

## Configuration persistence

`ResilientConfigurationStore` is intentionally compiled into the plugin assembly. The former generic adapter called `IDalamudPluginInterface.GetPluginConfig()` from `SentinelCore.Dalamud.dll`; current Dalamud discovers its live-update-safe generic config type through `Assembly.GetCallingAssembly()`, so the adapter assembly could not expose `SentinelHUD.Configuration` and fell back to legacy `$type` metadata. That path can return null across an in-game assembly update, after which the coordinator's former save-after-load behavior overwrote the file with defaults. The replacement reads the stable `IDalamudPluginInterface.ConfigFile`, creates one schema-specific backup before migration, invokes typed loading from `SentinelHUD.dll`, retries compatible raw JSON when old assembly metadata is the only problem, and never permits an unreadable un-backed-up file to be overwritten. The coordinator then applies explicit v1→v2→…→v10 migrations, debounces editor saves, flushes due saves during draw and performs a final flush during disposal. Schema 8 added only the marker rendering-style field; schema 9 added Off/Off/Manual quest-convenience defaults; schema 10 adds an independent Targeting Me Counter configuration and layout. Existing anchors, dimensions, field visibility, colours, awareness, radius, native-target, camera and convenience values remain untouched. Diagnostics exposes the load route and backup location.

## Convenience boundary

`AntiAfkService` is isolated from rendering and runs only on framework updates when explicitly enabled. At a ten-second cadence it obtains the current `InputTimerModule` and resets three positive inactivity counters after 30 seconds. It creates no thread and no simulated input. Disable/disposal stops writes; there is no persistent client setting to restore.

`QuestConvenienceService` is a separate plugin-lifecycle service and has no dependency on `HudRenderer`. It operates only on dedicated, currently visible addons. Ordinary Talk advancement is blocked whenever a response/Yes-No addon is visible. Cutscene skipping uses the live `UIInputModule.CutsceneSkipCallback` with `AgentCutscene.OpenSkipDialog`. Only a successful request creates a bounded confirmation token. During that token Sentinel resolves the exact addon ID from `AgentCutscene.SkipDialogAddonId`, falling back only to the dedicated `CutSceneSelectString` name during setup, validates its two-option list and invokes option zero with `AtkUnitBase.FireCallbackInt(0)`. The token survives a cutscene-condition transition while the modal opens, but is cleared after success, dismissal, timeout, territory change, logout, disable or disposal. Generic Yes/No and response addons are never eligible.

Choose-one reward policy is platform-neutral and tested independently. The Dalamud adapter re-reads up to five current `JournalResult` optional item slots, resolves every item through Lumina, derives equipment compatibility from current-job/ClassJobCategory data and recognizes Allagan pieces by stable item row IDs. A fingerprint of indices, item IDs and quantities is checked before selection and again before clicking the enabled Complete button. No addon pointer is retained between framework updates, Manual never dispatches an event, and guaranteed-only windows never enter the selection state machine.

## Future modules

The renderer and configuration model are organized by module kind so party/alliance, job gauges, status filtering, boss information, PvP data and optional versioned Sentinel IPC can be added without coupling the existing modules or requiring other Sentinel plugins.
